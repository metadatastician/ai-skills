### F7. A cleared error keeps its text and is still referenced by `aria-describedby`, so it can still be announced as the field's description
- Where: signup.html, `<input type="email" id="email" ... aria-describedby="email-hint email-error">` and the `else` branch of the submit handler (`err.hidden = true;`)
- Problem: When the email passes validation, the script sets `err.hidden = true` but leaves `err.textContent` as "Enter an email address in the correct format, like name@example.com". The input still points at `email-error` through `aria-describedby`. Under accessible name and description computation, content that `aria-describedby` references directly is included even when it is hidden, and Chromium-based browsers do this. A field that is now valid can therefore still have the old error as its description. This is visible to a user whenever the page stays on screen after the `else` branch runs: if the POST fails or is slow, or if the user comes back to the page with the Back button and the browser restores it from the back/forward cache.
- Who is affected: Screen-reader users (JAWS and NVDA with Chrome or Edge, and TalkBack with Chrome), and people with cognitive impairments who rely on what the screen reader tells them.
- Impact: The screen reader reads "We will only use this to send the newsletter. Enter an email address in the correct format, like name@example.com" on a field with no visible error and no `aria-invalid`. What is announced no longer matches what is shown, and the user may think the address is still wrong and change a correct one.
- Severity: 1
- Fix: In the `else` branch, also set `err.textContent = ''`. Better still, add `email-error` to `aria-describedby` only when there is an error, and set it back to `email-hint` when the error clears.
- Evidence: The `else` branch has only `err.hidden = true; email.removeAttribute('aria-invalid'); summary.hidden = true;`. It does not clear the text or change `aria-describedby`.
- Needs user testing: yes. Submit an invalid email, correct it, then submit again with the network throttled or blocked, and then come back to the page with the Back button. Check what NVDA + Chrome, JAWS + Edge and TalkBack + Chrome announce for the email field.
