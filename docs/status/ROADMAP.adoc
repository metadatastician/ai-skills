= AI Skills Roadmap
:toc:

This is the STATE journal for `ai-skills`. It holds the ultraplan the owner
agreed by selector on 2026-11-22. Each item is a PR the owner merges. Sizes
are rough: S is under a day of agent work, M is one to three days, L is more.
Waiting time (CI runs, owner review, key rotation) is not in the sizes.

== Current status

* Phase: incubating. Maturity: experimental.
* Nine skills exist. One (`seam-architect`) is built from data and checked.
  Eight are hand-written `SKILL.md` files that no tool checks.
* Two experiments are recorded, each with a single run: `katamorphe`
  (ceiling, all arms correct) and `nextgen-accessibility-team` (null).
* The skills tools run from Just recipes (`skills-build`, `skills-check`, `skills-test`, on `just test`) and from the `skills / build-check-test` workflow (PR #16).
* `mint-gates` and `analyze (actions, none)` are red on `main`.
* Signing uses the rotated key (`SHA256:u5pcpAz6…ZGc`) since 2026-11-22.
  The old, leaked key must never sign again.

== Scope decisions (owner, by selector, 2026-11-22)

[cols="1,3"]
|===
| Identity | A public library of agent skills, the tools that verify them, and the experiments that show each one works. Not a marketplace.
| Skills as data | All skills live as `data/<name>/` and are generated and checked. No hand-written skill ships.
| Evidence bar | Each skill has one sealed A/B experiment plus one repeat run. Null and negative results are reported as found and never re-run to get a win.
| Experiment runs | Agent sessions run the sealed protocols. The owner reviews before a result counts.
| `src/` | Idris2 specification of the skill format (manifest, sections, family rules). `check.mjs` is tested against it. Zig stays unwired unless a native tool is needed.
| `www/` | A read-only skills catalogue site, generated from `data/`.
| `features/ssg` | Builds the `www/` catalogue.
| `features/boj-server` | Runs the experiment harnesses in a sealed, verified environment.
| `features/panic-attacker` | Assail on `skills/tools`, Assault on `check.mjs` and `build.mjs` with hostile input.
| Tool gating | Just recipes on the golden path, and a required CI check.
| v1.0 skill set | The nine existing skills only. New skills come after v1.0 by the intake path.
| Distribution | Tagged releases: the generated `skills/` tree as a signed archive with checksums. Every tag meets this rule; the first tag is v1.0.0.
| Contributions | Owner-curated. Outside PRs welcome in the data layout, with checks passing and a two-run A/B.
| Plan home | This file. The hub of hubs gets a schedule card on each real change.
|===

== After v1.0 (ideal list)

* Skill intake path, including skills recovered from chat exports through
  the private overlay.
* A second, independent judge for experiments, such as human expert raters
  where a skill claims to help a group of people.
* A Zig native checker behind the ABI, only if a non-Bun consumer needs one.
* Migrate workflow YAML to KYAML once the lock-coverage shim is a required
  context (D280).
* Move the transitional `ijson-jcs` gate to a pinned `kyq` once it passes
  its tests.
